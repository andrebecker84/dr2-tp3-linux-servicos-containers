SERVIÇO: tp3-saudacao.service, unidade criada por mim em /etc/systemd/system
Criei uma unidade própria para não alterar o boot de um serviço do sistema e para
ter um caso real em que o daemon-reload é necessário.

O QUE CADA COMANDO FEZ
- daemon-reload (1ª vez): faz o systemd ler o arquivo novo. Antes dele a unidade
  não existiria para o gerenciador.
- enable --now: criou o link multi-user.target.wants/tp3-saudacao.service ->
  /etc/systemd/system/tp3-saudacao.service (é isso que "habilitar" significa: o
  target do boot passa a querer o serviço) e já o iniciou (--now).
- disable: removeu o link; o serviço continuou active, porque disable só mexe no
  boot seguinte, não no processo atual. enable o recriou.
- Depois de editar a Description com sed, o status avisou que o arquivo mudou no
  disco (NeedDaemonReload=yes). O daemon-reload releu a unidade e o aviso sumiu.

ESTADO FINAL DO SERVIÇO
- UnitFileState ....: enabled (sobe no próximo boot)
- ActiveState ......: active (exited): oneshot com RemainAfterExit=yes
  roda o comando uma vez e continua "ativo" sem processo.
- Description ......: TP3 - servico de exemplo (v2)
- NeedDaemonReload .: no
