CONCLUSÕES TÉCNICAS
- cd: COMANDO INTERNO do bash (type: "cd is a shell builtin"). O which não acha
  nada, porque só procura arquivos no PATH. Precisa ser interno: um processo
  filho não consegue mudar o diretório atual do shell pai.
- ls: ALIAS (ls --color=auto, do ~/.bashrc) que aponta para o BINÁRIO /usr/bin/ls.
  type -a mostra as camadas na ordem em que o shell as procura: alias,
  builtin/função e, por fim, os arquivos do PATH. /usr/bin/ls é um link para
  /usr/lib/cargo/bin/coreutils/ls: no Ubuntu 26.04 o coreutils padrão é o
  uutils, reescrito em Rust. file -L: ELF 64-bit, ligado dinamicamente.
- gunzip: SCRIPT. O which e o type acham /usr/bin/gunzip, mas o file diz "POSIX
  shell script" e a primeira linha é o shebang #!/bin/sh: o kernel lê o shebang
  e executa o interpretador /bin/sh passando o script como argumento.
- vim: BINÁRIO por trás de dois links simbólicos. /usr/bin/vim -> /etc/alternatives/vim
  -> /usr/bin/nvim (sistema de alternativas do Debian). O file sem -L só diz
  "symbolic link"; com -L segue a cadeia até o ELF. Neste Ubuntu, vim abre o
  Neovim; o Vim original fica em /usr/bin/vim.basic (usado no Ex. 11).
- echo existe nas duas formas: builtin do bash e /usr/bin/echo. O builtin vence,
  porque o shell o encontra antes de procurar no PATH.
ORDEM DE RESOLUÇÃO DO BASH: alias -> palavra reservada -> função -> builtin -> PATH.
